# 공동 수사와 사건기록 연동 구현 계획

**Goal:** 승인된 공동 수사 흐름과 행동 화면의 사건기록 자동 대조를 구현하고 기존 방을 보존한 상태로 배포한다.

**Architecture:** 새 사건은 flowVersion 2로 시작하며 비밀 준비를 동시에 받는다. 공개 준비 상태에는 행동 종류를 포함하지 않는다. 기존 저장 사건은 원래 순차 흐름을 유지한다. 공유 선택 규칙을 서버와 브라우저가 함께 사용한다.

**Tech Stack:** 기존 Node.js 서비스, 순수 JavaScript UMD, Vercel, 기존 저장소.

**Spec:** 사용자가 승인한 이번 대화의 동시 비밀 준비·무료 메모/제안·능동 증언과 행동 화면의 사건기록 연동안.

## Global Constraints

- 인물·장소·도구·시간 각각 12개, 총 7일, 최종 고발은 인물 한 명.
- 원본 증거는 불변. 검증 전 제안과 진술은 확정 사실이 아니다.
- 공식 수사 하루 1회, 기존 거짓말·봉쇄·보호·기억·제보 제한 유지.
- 용의자의 정체 후보와 진범 후보는 별도로 유지.
- 닉네임/비밀번호 재접속 및 기존 v3/v4 진행 상태 보존.

## Review Focus

- 두 사람이 같은 시점에 준비해도 중복 차감이나 상태 유실이 없어야 한다.
- 준비 완료 표시나 선택 필터가 비공개 행동·봉쇄·타인의 단서를 노출하지 않아야 한다.
- 이미 읽은 원본, 확정된 질문 가정은 최신 상태에서 재확인하고 무효 행동에 횟수를 쓰지 않아야 한다.
- 봉쇄·미진술은 재시도 가능하며 수동 X나 제안이 공식 제외로 오인되지 않아야 한다.
- 모바일에서 작성 중인 선택을 유지하며 카드 수첩과 행동창을 오갈 수 있어야 한다.
