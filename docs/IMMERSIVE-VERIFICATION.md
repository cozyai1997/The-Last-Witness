# 몰입형 진행·컴퓨터 연습 검증 — 3.2.0

2026-10-17. 기존 온라인 계정과 저장소를 유지하면서 사용자 피드백을 적용했다. 규칙은 [ONLINE-RULES.md](ONLINE-RULES.md), 동작 설계는 [IMMERSIVE-DESIGN.md](IMMERSIVE-DESIGN.md)에 있다.

| 11 | 모든 진행 단계에서 사용할 수 있는 하단 플로팅 채팅. 자유 발언은 공식 증거와 분리한다. |

## 자동 검사

- `npm test`: **82/82 통과**. 엔진·서비스·계정·UI·컴퓨터 연습 검사다.
- `npm run test:security`: **20/20 통과**. 각 역할 응답의 비밀 정보 분리, 권한과 원문·증거 보존을 확인했다.
- `npm run test:auth-review`: **5/5 통과**. 동시 계정 등록·로그아웃·토큰 교체와 만료 후 같은 역할 복귀를 확인했다.
- 온라인 UI의 **2~6인 각각 5라운드**가 실제 서비스와 최소 DOM 환경에서 질문 → 답변 → 검토/검증 → 확인 → 다음 날 → 최종 고발을 완료했다. 이는 실제 브라우저 배치 검사와 구분한다.
- 컴퓨터 연습 **15개 검사**에서 2~6인 각각 사람 탐정·범인 게임을 완료했다. 봇 탐정이 허용된 기록으로 판단하고 숨은 정답으로 추리 결과를 바꾸지 않는 것을 확인했다.
- 실제 Supabase 연결 로컬 HTTP: **6인·5라운드·359개 요청 통과**, 평균 445ms·최대 2391ms. 중간 재로그인, 진행 중 채팅, 별도 2인 간소화, 결과 검증과 최종 단계까지 검사했다. [안전 결과 JSON](IMMERSIVE-LOCAL-HTTP-RESULT.json) 참조.

## 실제 Chrome 확인

로그인하지 않고 탐정과 범인으로 각각 연습했다. 시작 이야기·봉인된 개인 창, 차례 메뉴, 질문 미리보기와 답변의 필기체 표시, 탐정의 답변 검증 후 기회 0회 및 추가 검증 비활성화를 확인했다. 범인 게임은 5일째 컴퓨터 탐정의 최종 고발과 결말까지 진행해 WIN/LOSE와 회색 패배 프로필을 확인했다.

질문을 받은 단계에서도 하단 채팅을 작성·전송했고 내용이 남았다. 프로필 자원 설명을 마우스와 단일 클릭으로 표시했다. 390×844 CSS 화면에서 질문창·자원 설명·고정 채팅/음악 버튼이 가로 넘침 없이 배치됐다. 실제 휴대전화의 터치·가상 키보드, iOS Safari·Firefox는 별도 미검증이다. Chrome 모바일 크기에서의 화면 검사는 실기기 검사와 구분한다.

## 보존과 한계

새로운 2인 규칙은 `rulesVersion:2`인 새 사건에 적용한다. 이미 진행 중인 이전 버전 사건은 시작 단서·역할·개인 순서를 변경하지 않는다. 서버는 계속 온라인 실제 정답을 보관하고 본인에게 허용되는 정보만 보낸다. 공개 연습 엔진은 별도 로컬 가상 사건용이며 온라인 비밀 데이터가 포함된 파일이 아니다.

매일 수사는 1회다. 방금 답변의 즉시 검증은 질문 뒤 같은 날 하는 검토이며 기존 감식/과거 진술 검증과 **전체 키트 1개를 공유**한다. 새로운 공용 기회가 생기지 않는다. 2인전의 불필요한 공개 행동을 없앤 것은 시작 정보량을 추가한 것이 아니다. 자동·봇 검사를 사람 사이의 승률이나 장기 밸런스·재미 검증으로 해석하지 않는다.

## 운영 배포

빌드·운영 READY·운영 주소의 정적 파일과 실제 게임 요청을 구분해 확인한다. 배포 뒤 운영 검사 결과는 별도 JSON과 최종 전달 기록에 남긴다. 기존 사용자 계정·방을 초기화하거나 삭제하지 않는다.
