# 탐정 수사·은폐 피드백 검증 — 3.3

검증 날짜: 2026-10-17. 이 기록은 여섯 가지 추가 피드백의 구현과 회귀 검사 범위를 설명한다. 이전 버전의 운영 검증 기록은 당시 결과로 보존한다.

## 요구사항과 확인 방법

| 요구사항 | 구현과 확인 |
|---|---|
| 거짓 검증 결과의 빨간 테두리 | 실제 검증이 끝난 뒤 원래 진술과 확인한 실제 값이 다를 때만 `is-verified-lie`를 표시한다. 빨간색과 함께 거짓 확인 문구를 제공한다. 참·미검증 답변과 과거 진술 감사의 비교 대상도 검사한다. 원문을 실제 값으로 덮어쓰지 않는다. |
| 탐정의 인물 힌트 1개·현장 단서 1개 | 규칙 3으로 시작한 2~6인 사건에서 인물 항목 한 개와 장소 항목 한 개를 탐정에게 배분한다. 목격자는 나머지 항목의 참 단서 하나씩을 받는다. 각 인원·100개 시드, 합계 500개 사건에서 개수·종류·비중복·실제 정답과의 일치를 검사한다. |
| 완료·은폐·보유 단서의 질문 자동 제외 | 개인 참 단서·공식 사실·완료된 이진 답변·모름·은폐된 질문 이력으로 질문 항목을 걸러 낸다. 항목을 바꾸면 가정 값과 문구도 함께 정규화한다. 빈 목록에서는 질문을 비활성화하며 기본 항목을 몰래 다시 넣지 않는다. |
| 최종 고발 후보 자동 제외 | 공개 공식 증거와 기존의 거짓말 최대 2회 후보 조건에 탐정의 참 단서를 더한다. 최종 선택에서는 탐정의 수동 제외 메모도 반영한다. 전부 제외했을 때 확정을 막고 메모 초기화를 제공한다. 검증 전 진술 한 개를 확정 증거처럼 취급하지 않는다. |
| 은폐 안내의 자연스러운 순서 | 안내 문장이 타이핑되는 동안 다음 진행을 막고 빠르게 보기는 문장만 완성한다. 읽는 중 새 라운드가 도착해도 현재 글을 보존하고, 계속을 누르면 최신 DAY 장면과 현재 차례 메뉴를 표시한다. 반복 동기화·채팅·전송 중 화면 갱신으로 타이핑을 다시 시작하지 않는다. |
| 범인에게만 은폐 실패 안내 | 봉인이 실제 수사를 막았는지 확정된 뒤 범인 본인의 안전한 응답에만 결과를 넣는다. 정상 질문은 답변 완료 전 실패 여부를 알리지 않는다. 공범·다른 역할·공개 응답에는 실패 결과를 넣지 않는다. 늦게 접속한 범인도 읽을 수 있고, 화면을 떠나면 개인 안내를 가린다. |

## 실제 검사와 범위

- 최종 전체 자동 검사 **112/112 통과**를 확인했다. 실행은 약 22초가 걸렸으며 실패·취소·건너뛰기는 없었다. 처음 확인한 109개 검사에 채팅·전송 중 타이핑 보존, 개인 안내의 창 전환 보호, 타이핑 중 다른 접속에서 받은 검증 결과 반영 검사를 추가한 결과다.
- UI 검사 **22/22 통과**에는 기존 인증·연습·2~6인 5라운드 전체 진행과 이번 피드백의 흐름 검사 10개가 포함된다. 새 흐름 검사만 따로 실행한 결과도 **10/10 통과**했다.
- 개인정보 보호 검사와 타이핑 도중 검증 결과 변경 검사는 각각 수정 전 실패를 재현했고, 수정 후 같은 검사에서 통과했다. 개인 안내를 가린 뒤 다시 초점을 받는 흐름, 취소한 이전 타이핑 콜백의 영향 차단, 최신 검증 결과의 빨간 테두리 반영을 확인했다.
- UI 검사는 실제 게임 서비스와 UI 스크립트를 최소 DOM에서 연결한다. 타이핑은 완료·취소 시점을 제어하는 모형을 사용하여 느린 사람의 화면에 다음 동기화가 도착하는 상황을 재현한다. 이 검사가 화면의 실제 색상·글꼴·터치 동작을 측정하지는 않는다.
- 서버 검사는 공식 증거의 진실성, 역할별 응답 제한, 공개·개인 응답 분리, 기회 소모, 기존 사건 보존을 확인한다. 새 단서 배분으로 이미 진행 중인 이전 규칙 사건을 다시 배분하거나 정답을 바꾸지 않는다.

## 규칙 해석과 남은 선택

질문 필터는 같은 항목을 계속 묻는 일을 줄인다. 다섯 항목 중 탐정이 처음 아는 두 항목을 제외하면 새 질문은 최대 세 항목이다. 나머지 라운드는 기록 확인·과거 진술 검증·수사 넘기기로 끝낼 수 있으며, 최종 고발까지 다섯 라운드라는 진행은 유지한다.

현장 감식은 질문 필터와 목적이 다르다. 이미 참값을 아는 항목은 제외하되, 미검증 답변·모름·과거 은폐로 끝난 항목의 진실을 확인하는 데 남은 공용 키트 한 개를 쓸 수 있다. 질문 이력 때문에 이 검증 경로까지 없애지는 않는다.

공개 사건판의 자동 후보 수는 공개 정보로 계산한다. 탐정의 고발 창에서만 자신의 참 단서를 더한다. 수동 제외는 사용자의 추리 메모이며 참임을 서버가 보장하는 증거가 아니다. 잘못 제외한 정답은 메모 초기화로 되돌릴 수 있다.

은폐 안내의 화면 순서가 다른 기기의 진행을 정지시키지는 않는다. 읽기를 마치면 그 시점의 최신 사건 상태로 이어진다. 이미 읽은 안내의 중복 방지 기록은 사건별로 구분한다.

## 인원별 균형 위험

| 인원 | 이전 시작 참 단서 합계 | 새 합계 | 모두 공유한 뒤 공식 참 단서만으로 남는 조합 |
|---|---:|---:|---:|
| 2 | 2 | 2 | 8개 |
| 3~4 | 2 | 3 | 4개 |
| 5~6 | 2 | 4 | 2개 |

위 조합 수는 다섯 이진 항목이 모두 독립이고 시작 단서가 서로 다르다는 사건판 구조에서 계산한 정보량이다. 실제 사람의 승률을 측정한 수치가 아니다. 공개 전 개인 단서를 공유하는 시점, 질문 대상의 선택, 거짓말과 은폐의 선택은 플레이마다 다르다.

특히 5~6인에서는 목격자가 협력해 빠르게 단서를 공유하면 탐정이 자기 단서를 합쳐 네 항목의 실제 값을 안다. 남은 한 항목을 키트로 확인할 수 있어 수사 진영이 매우 유리해질 위험이 있다. 범인 진영의 은폐가 최대 세 번인 동안 수사는 다섯 번이므로, 적절히 협력하고 감식을 기다리는 플레이에 대해 단순히 거짓말 횟수만 유지했다고 균형이 보장되지는 않는다.

이번 변경은 요청한 탐정의 두 종류 단서를 적용하며 역할별 기회와 기존 사건을 보존한다. 추가 균형 조정은 목격자 단서의 중복 허용·공개 방식·감식 조건 등을 별도로 플레이테스트하여 결정할 대상이다. 자동 검사 통과나 컴퓨터 연습만으로 양 진영이 균형을 이룬다고 주장하지 않는다.
