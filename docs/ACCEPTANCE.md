# 온라인 인수 검사 기록

이 문서의 아래 실행 수치는 3.0 확장판의 이력이다. 3.1 계정 복귀·BGM의 최신 검사는 [ACCOUNT-BGM-VERIFICATION.md](ACCOUNT-BGM-VERIFICATION.md)를 확인한다. 3.1부터 계정으로 다시 로그인해 방과 역할을 복구하며 방 보관 기간은 마지막 플레이부터 30일이다.

이 문서는 소스 검토, 실행한 자동 검사, 실제 배포·브라우저 검사를 구분한다. 계획에 적힌 항목은 통과 결과가 아니다. 사람끼리의 승률·재미는 별도 플레이 테스트 대상이다.

## 계약과 범위

- 2~6명, 최대 5라운드, 참가자당 닉네임 게스트 세션.
- `POST /api/room`: `login`, `create`, `join`, `poll`, `ready`, `start`, `action`, `restart`, `leave`, `kick`.
- 세션은 로그인 시점, 방은 생성 시점부터 24시간 유효. 폴링으로 연장하지 않는다. 게스트 로그인은 본인 인증이 아니다.
- 서버가 역할·사건·턴·공식 기록을 관리한다. 동시 갱신은 낙관적 버전 비교로 충돌을 확인한다.
- 활성 화면 약 2초 폴링으로 상태를 공유한다. 웹소켓 연결을 전제로 하지 않는다.

## 실제 실행 결과 — 2026-10-17

- `npm test`: **42개 통과, 실패 0개**. 온라인 서비스·HTTP 검사 18개, 기존 규칙 엔진 검사 19개, 실제 서비스와 UI를 연결한 2~6인별 DOM 검사 5개다. UI 검사는 각 인원 구성의 5라운드 완료, 개인 정보 가림, 입력·초점·모달 유지와 발언 HTML 처리를 확인한다. 실제 브라우저 렌더링과는 구분한다.
- `npm run test:security`: 독립 보안 검사 19개 통과. 재현 파일은 `tests/security-review.cjs`다.
- 실제 Supabase 연결 로컬 HTTP: **6인·5라운드·287개 요청 통과**, 평균 301ms, 최대 1559ms. [결과](LOCAL-DURABLE-HTTP-RESULT.json).
- 실제 Vercel 운영 주소 `https://the-last-witness-pi.vercel.app`: **7개 독립 게스트 세션, 최대 6인 입장, 5라운드, 287개 요청 통과**, 평균 401ms, 최대 2366ms. 동시 입장과 7번째 입장 거부, 개인별 비밀 분리, 위조 행동 거부, 보호·봉쇄, 진영 거짓말 공유, 공식 감사의 원문 보존, 최종 승리, 세션 재조회, 재시작·퇴장을 검사했다. [결과](LIVE-HTTP-RESULT.json), 재현 파일 `tests/live-http.cjs`. 6명의 실제 사람 또는 6대 휴대폰을 사용한 검사는 아니다.
- Chrome의 별도 두 탭에서 각자 게스트 로그인·초대 링크 입장·준비·역할 확인·개인 행동·탐정 질문·범인 답변·자유 발언·최종 고발을 실제 조작해 양쪽 승패 일치, 새로고침 후 기존 역할 복구와 방장 재시작을 확인했다. 이 두 탭 검사는 로컬 HTTP + 실제 Supabase를 사용했다.
- 독립 서비스 검사: **19개 통과**. 2~6인별 정확한 역할·능력 횟수·서로 다른 시작 단서 2개를 확인했다. 별도 6인 게임의 공개 전·개인 행동·질문 답변·토론·종료 등 **18개 상태 묶음에서 각각 6명의 응답**을 검사했다. 결과는 [SECURITY-REVIEW.json](SECURITY-REVIEW.json)에 있다.
- 실제 Supabase 저장소 검사: 없는 비밀값과 틀린 비밀값은 각각 **401**, 여섯 개의 동시 버전 비교 갱신은 **정확히 하나만 성공**, 공개 테이블 직접 조회 **404**, 비공개 스키마 프로필 조회 **406**을 확인했다. 배포 담당자의 실제 실행 결과를 읽고 [STORAGE-SMOKE.json](STORAGE-SMOKE.json)으로 보존했다. 앱 전체의 다중 서버 부하 검사와는 구별한다.

독립 검토에서 로그인 토큰이 공개 닉네임·요청 번호로 다시 생성되어 기존 게스트를 사칭할 수 있는 문제를 재현했다. 서버를 **로그인마다 새 난수 토큰을 발급**하도록 수정한 뒤 같은 입력을 다른 접속자로 보내도 별도 토큰과 빈 방 상태를 받는 회귀 검사를 통과했다. 인증된 방 행동의 중복 요청 방지는 유지한다. 현재 확인한 범위에서 이 발견 사항은 해결됐다.

## 기존 엔진 독립 소스 검토

검토 대상은 기존 `party-engine.js`다. 다음은 코드에서 확인한 특성과 온라인 적용 시 필요한 경계다. 서비스 적용·배포 확인은 별도 결과에 기록한다.

| 항목 | 소스 검토 결과 | 온라인 서버 요구 |
|---|---|---|
| 공개 정보 | `publicView`는 허용한 공개 필드만 복사하며 진행 중 정답·역할·개인 단서·거짓말 사용량·봉인·보호를 제외 | 원본 상태를 응답하지 않고 공개 투영을 사용 |
| 개인 정보 | 기존 `privateView`는 로컬 전달 방식의 현재 차례만 허용 | 인증된 본인 좌석에만 개인 투영. 온라인의 본인 상시 열람은 명시적으로 처리 |
| 종료 공개 | `finished`에서 정답·전체 역할·진술 참거짓 공개 | 클라이언트가 종료 상태를 임의 지정하지 못하게 유지 |
| 행동자 | 엔진은 제공된 `actorId`를 차례·역할과 비교 | 서버가 인증 세션의 실제 좌석에서 ID를 정하고 입력 ID를 신뢰하지 않음 |

| 비밀 상태 | 정답·전체 역할은 원본 게임에 존재 | 서버 전용 보관. 난수 시드·원본 상태·저장소 값·토큰 해시를 공개 응답에 포함하지 않음 |

공개 응답을 숨기는 것과 브라우저에 전체 비밀을 받은 뒤 화면에서 감추는 것은 다르다. 응답 원문 검사로 본인에게 허용되지 않은 비밀 필드가 없는지 확인한다. 클라이언트의 버튼 숨김만으로 권한을 판단하지 않는다.

## 기록 원칙

소스 검토만 한 항목은 실행 통과로 바꾸지 않는다. 자동 검사에는 명령·검사 수·결과·대상 코드를, 배포 검사에는 실제 URL·독립 세션 수·확인 흐름을 기록한다. 아직 수행하지 않은 만료 시간 경과·다중 인스턴스·사람 플레이는 미검증으로 남긴다.

24시간은 서버에서 판정하는 절대 유효기간이다. 만료 레코드 정리는 요청 처리 때 수행하며, 정확히 만료 시각에 물리 삭제하는 예약 작업을 검증한 것은 아니다. 게임 중 연결이 끊겨도 다른 사람에게 좌석을 자동 양도하지 않으며 진행 중 강퇴·나가기·중도 재시작을 지원하지 않는다. 원래 게스트 세션으로 돌아와야 해당 차례를 이어갈 수 있다.
