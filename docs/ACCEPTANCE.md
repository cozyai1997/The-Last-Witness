# 온라인 인수 검사 기록

이 문서는 소스 검토, 실행한 자동 검사, 실제 배포·브라우저 검사를 구분한다. 계획에 적힌 항목은 통과 결과가 아니다. 사람끼리의 승률·재미는 별도 플레이 테스트 대상이다.

## 계약과 범위

- 2~6명, 최대 5라운드, 참가자당 닉네임 게스트 세션.
- `POST /api/room`: `login`, `create`, `join`, `poll`, `ready`, `start`, `action`, `restart`, `leave`, `kick`.
- 세션은 로그인 시점, 방은 생성 시점부터 24시간 유효. 폴링으로 연장하지 않는다. 게스트 로그인은 본인 인증이 아니다.
- 서버가 역할·사건·턴·공식 기록을 관리한다. 동시 갱신은 낙관적 버전 비교로 충돌을 확인한다.
- 활성 화면 약 2초 폴링으로 상태를 공유한다. 웹소켓 연결을 전제로 하지 않는다.

## 기존 엔진 독립 소스 검토

검토 대상은 기존 `party-engine.js`다. 다음은 코드에서 확인한 특성과 온라인 적용 시 필요한 경계다. 서비스 적용·배포 확인은 별도 결과에 기록한다.

| 항목 | 소스 검토 결과 | 온라인 서버 요구 |
|---|---|---|
| 공개 정보 | `publicView`는 허용한 공개 필드만 복사하며 진행 중 정답·역할·개인 단서·거짓말 사용량·봉인·보호를 제외 | 원본 상태를 응답하지 않고 공개 투영을 사용 |
| 개인 정보 | 기존 `privateView`는 로컬 전달 방식의 현재 차례만 허용 | 인증된 본인 좌석에만 개인 투영. 온라인의 본인 상시 열람은 명시적으로 처리 |
| 종료 공개 | `finished`에서 정답·전체 역할·진술 참거짓 공개 | 클라이언트가 종료 상태를 임의 지정하지 못하게 유지 |
| 행동자 | 엔진은 제공된 `actorId`를 차례·역할과 비교 | 서버가 인증 세션의 실제 좌석에서 ID를 정하고 입력 ID를 신뢰하지 않음 |
| 메모 발언자 | `ADD_NOTE`는 별도 `speakerId`를 받음 | 인증 좌석으로 고정해 타인 사칭 방지 |
| 비밀 상태 | 정답·전체 역할은 원본 게임에 존재 | 서버 전용 보관. 난수 시드·원본 상태·저장소 값·토큰 해시를 공개 응답에 포함하지 않음 |
| 다섯째 라운드 지목 | 기존 엔진은 수사 선택 단계에서도 지목 가능 | 온라인 래퍼에서 5라운드 수사 처리 후 토론 단계의 지목을 요구 |

공개 응답을 숨기는 것과 브라우저에 전체 비밀을 받은 뒤 화면에서 감추는 것은 다르다. 응답 원문 검사로 본인에게 허용되지 않은 비밀 필드가 없는지 확인한다. 클라이언트의 버튼 숨김만으로 권한을 판단하지 않는다.

## 기록 원칙

소스 검토만 한 항목은 실행 통과로 바꾸지 않는다. 자동 검사에는 명령·검사 수·결과·대상 코드를, 배포 검사에는 실제 URL·독립 세션 수·확인 흐름을 기록한다. 아직 수행하지 않은 만료 시간 경과·다중 인스턴스·사람 플레이는 미검증으로 남긴다.
