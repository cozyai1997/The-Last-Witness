## 연습 경계

새 화면은 WitnessPractice.start에 rulesVersion:4를 명시한다. 어댑터는 WitnessSevenPractice로 라우팅하고 full engine을 /seven-practice-engine.js에서 필요할 때 불러온다. 기존 명시적 3.x 호출과 기존 테스트의 기본 경로는 이전 엔진으로 남는다.

새 어댑터는 makeGame·act·turnOwner와 publicView·privateView를 사용한다. 사람 응답과 컴퓨터 정책에는 한 참가자의 privateView 복사본만 전달한다. 컴퓨터가 받는 값으로 다른 카드나 회복 전 S 정체를 읽을 수 없다. 범인·공범만 caseSecret으로 허용된 진상을 받는다. 탐정 고발은 본인 후보 목록에서 선택하며 숨은 정답으로 덮어쓰지 않는다.

연습 검사는 가능한 인원별 모든 역할(중복 W 제외 18조합)에서 DAY 7 결과·복기를 끝까지 진행한다. S가 포함되면 기억 두 번과 제보 한 번의 기록도 검사한다. 추가로 다음을 확인한다.

- 계정·방 네트워크 요청과 온라인 로그인 저장소 접근 0회.
- 응답 수정이 내부 상태를 바꾸지 않는 분리된 투영.
- 현재 차례 검사와 로그인한 사람의 actor 강제 지정.
- 수정 전 화면의 revision 거부와 같은 요청 중복 처리 방지.
- 재시작의 새 사건 식별자, 중단된 과거 타이머의 무효화.
- 실제 후보 목록과 다른 숨은 정답을 사용하는 탐정 정책 금지.
- S 정체를 읽으면 실패하는 검사 객체에서 기억 행동만 선택.
- 공개 catalog를 바꾸지 않고 full generated engine을 지연 로딩.

## 인증·서버 통합

서비스 검사는 임시 계정을 등록한 뒤 기존 계정 로그인 경로로 다시 접속한다. 별도 7번째 계정으로 6석 정원 초과를 거부하는지도 확인한다. 네 사건은 같은 계정과 방을 재사용하고 각 사건 사이에는 종료→대기실→전원 준비→새 사건을 거친다.

| 사건 | D의 고발 | S 제보 | 기대 결과 |
|---|---|---|---|
| 실제 캐릭터 정답 | 실제 C 캐릭터 | DAY 3 정확 제보 | D·W 승리, S 개인승리·선제추적 |
| 중립 동시승리 | C·S 이외 다른 인물 | DAY 3 정확 제보 | C·A 승리, S 개인승리·선제추적 |
| 자기 고발 우선 실패 | 실제 S 캐릭터 | DAY 6 정확 제보 | C·A 승리, S 실패 |
| 생존·마감 | 실제 C 캐릭터 | 미제보 | D·W 승리, S 생존·목표미달 |

각 사건에서 S 후보 3→2→1과 earned characterId 시점, DAY 1~6 조기 고발 차단, DAY 7 마지막 수사 전 차단, 일곱 번 검토 확인, 인물 하나 ACCUSE, 종료 후 6명 동일 복기를 검사한다. S 제보가 다른 사람 개인 카드·공개 로그에 나타나지 않고 본인 접수에도 정오답 필드가 생기지 않아야 한다. 제보를 이미 했다면 다음 개인 턴 재제출을 거부한다. 미제보 사건은 DAY 6 S 본인 행동 직후의 늦은 제출과 DAY 7 본인 턴의 제출을 모두 거부한다.

첫 사건에서는 C·A 공동 거짓말 두 번과 유보 한 번, 같은 항목 재질문, 키트 하나로 현재 답변 참거짓 검증, 원문 보존, 원본 조회, 단계별 자유 채팅을 확인한다. 여섯 계정 모두 다시 로그인해 캐릭터·기억·자원·제보·기록이 같은지 비교하고 이전 토큰 거부를 검사한다. S 로그아웃 뒤 로그인해도 같은 자리를 이어가야 한다.

별도 서비스 검사는 인증된 actor만 행동하고 위조 role·characterId·secretNPC는 권한이나 정답으로 채택되지 않는지 확인한다. 두 개의 동시 동일 요청은 차례를 한 번만 소비하며 오래된 revision과 객체형 채팅 입력은 상태를 바꾸지 않는다.

기존 규칙 3 방은 새 기본 서비스 인스턴스에서 읽어도 투영이 그대로여야 하고 다음 행동도 이전 엔진으로 처리해야 한다. 반면 옵션 없는 새 서비스가 만드는 사건은 rulesVersion4·maxRounds7이어야 한다. 저장소 초기화나 DB 변경은 하지 않는다.

## 자동 검사 실행

~~~sh
node --test tests/seven-practice.test.cjs tests/seven-service.test.cjs tests/practice.test.cjs
~~~

2026-10-17에 인물·장소·도구·시간 각각 12개의 최종 카탈로그와 최신 생성본으로 새 연습 24개·새 서비스 3개·기존 연습 16개, 합계 **43개가 모두 통과**했다. full generated bundle 지연 로딩과 SHA-256 동일성, 로딩 중 종료 취소도 포함한다. 다중 시드 정책 검사는 2~6인 × 20시드, 총 100사건을 7일까지 끝냈다. 이 결과는 사람끼리의 승률을 뜻하지 않는다.

실제 HTTP 실행은 실행 중인 서버를 대상으로 한다.

~~~sh
BASE_URL=http://127.0.0.1:4205 TEST_REPORT=docs/SEVEN-LOCAL-HTTP-RESULT.json node tests/seven-live-http.cjs
~~~

2026-10-17 19:34 KST 새 서버 4205에서 인물·장소·도구·시간 각각 12개의 최종 구성으로 실제 로컬 HTTP를 완료했다. 공개 연결 자료도 인물 12·장소 12행과 각 연결 범위 6개인지 검사해 과거 엔진 캐시로 통과하지 못하게 했다. 550요청, 응답 평균 496ms·최대 4,017ms, 비공개 경계 439회, 종료 복기 비교 24회, 재로그인 13회가 모두 통과했다. 네 사건은 각각 실제 C 캐릭터 정답·C와 S 동시승리·S 자기 고발 우선 실패·미제보 중립 생존을 확인했다. 결과: [SEVEN-LOCAL-HTTP-RESULT.json](SEVEN-LOCAL-HTTP-RESULT.json). 완료 후 여섯 참가자는 방을 떠났다. 계정 비밀번호·토큰·방 코드·정답은 저장하지 않았다.

PowerShell에서는 해당 환경변수를 먼저 설정한다. CLI 경로는 POST /api/room을 직접 호출하고 Cache-Control:no-store도 확인한다. 보고서는 날짜·대상·검사 수·판정·응답 시간 등 안전한 통계만 저장한다. 닉네임·비밀번호·토큰·방 코드·비밀 좌표를 저장하지 않는다. 검증용 계정은 대상 저장소의 계정 수명 정책을 따르며 완료 후 방은 떠난다.

## 정보·균형 해석

엔진의 다중 시드 검사는 확정 자료의 진실성, 원본 재열람의 동일성, 전체 원본을 읽은 후에도 여러 인물과 C/S가 남는지, 도구·시간 연결 자료가 후보를 거르는지 확인한다. 이것이 사람끼리의 승률 50%나 재미를 뜻하지 않는다.

컴퓨터는 규칙 학습용 정책이다. 후보를 공정하게 받더라도 최적 추리나 최적 허위 진술을 수행한다는 보장은 없다. 실제 사람 대화와 역할 주장, 선택 순서의 전략 균형은 별도 플레이 관찰이 필요하다.

## 이야기 일관성 검토

[사건 대본](SEVEN-STORY.md)을 7일 규칙과 비교했다. 12개씩의 공개 보드, 범행 당일 18:00~21:00의 15분 구간과 이후 수사일의 구별, 인물 하나 고발, 관찰·원본·미검증 진술의 구분, S 정체·제보의 비공개, S 독립 결과와 본인 고발 실패 우선순위가 규칙과 일치한다. 그림의 장식 시계가 실제 시간 판정이 되는 것으로 설명하지 않는다. 이 문서 검토는 실제 브라우저 연출 수락과 별도다.

## 최종 인수 기록

최종 기능 인수: `npm run build`, 전체 회귀 **203/203**, 기존 보안 **20/20**, 인증 경쟁 상태 **5/5**가 통과했다. 별도 코드 검토에서 발견한 상세 카드 제외 표시, 질문 이력의 가정 누락, 비공개 봉쇄 결과, 공개 수사 제안 표시를 고치고 회귀 검사에 포함했다. W/S의 공개 봉쇄 안내와 종료 후 일회성 필기체 대본도 검사했다.

최신 코드의 새 서버 **4206**에서 실제 HTTP **550요청**이 통과했다. 인물·장소·도구·시간 각각 12개, `fieldReferenceVersion:2`, 인물별 서로 다른 공개 기록 조합 6개, 조합 검증 **1,728회**, 비공개 경계 **439회**, 6명 동일 복기 **24회**, 재로그인 **13회**를 확인했다. 평균 응답 **532ms**, 최대 **4,568ms**. 과거 4205 결과는 이 최종 결과로 대체되었다. 자격정보는 저장하지 않았다.

직접 Chrome 플레이에서 6인 용의자로 DAY-01부터 DAY-07까지 진행했다. 정체 후보 3→2→1, DAY-03 이유를 포함한 봉인 제보, 같은 제보 재확인 및 수정 불가, 모르는 질문의 미진술, 기록 보호, 범인 진영 승리와 용의자 생존·목표미달의 별도 판정, 전체 복기 접근을 확인했다. 추가 탐정 플레이와 모바일/운영 검증은 배포 인수 때 기록한다.

장소·도구·시간의 적합성은 [별도 검토](SEVEN-EVIDENCE-REVIEW.md)에 기록했다. 초기 부분 자료의 기여가 낮아 인물별 장소·도구·시간의 **묶인 기록 조합**으로 보완했다. 500개 사건에서 각 요소 제거 시 후보 인물 복구가 장소 73·도구 42·시간 39건이었다. 전 원본으로 진범이 자동 확정되지 않았고 C와 S가 유지됐다. **1,000건 컴퓨터 정책 검사의 탐정 승리 65.4%/67.2%는 탐정 쪽 우세를 보인 정책 표본이며 사람 승률이 아니다.** 사람 대화·봉쇄 전략의 실전 균형은 추가 관찰이 필요하다.

GitHub 반영과 운영 HTTP·정적 자산·브라우저 인수 결과는 실제 배포가 끝난 뒤 아래에 덧붙인다. 이 단계의 로컬 성공을 운영 성공으로 해석하지 않는다.
