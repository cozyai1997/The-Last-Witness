# 동시 비밀 준비와 사건기록 연동 검증

새로 시작하는 7일 사건에는 `flowVersion: 2`를 사용한다. 저장된 기존 7일 사건에서 이 필드가 없으면 기존 순차 진행을 유지하며, 기존 5일 사건도 자동 전환하지 않는다.

## 서버 통합 검증

`tests/seven-pacing-service.test.cjs`의 6개 통합 검증이 통과했다.

- 차례 대표로 표시되는 참가자가 아닌 용의자도 비밀 준비를 완료할 수 있다. 위조한 참가자 ID는 무시하고 로그인한 좌석에 행동을 연결한다.
- 기억 복원 종류와 진행 내용은 다른 좌석에 노출되지 않는다. 공개되는 것은 동일한 준비 완료 상태이며, 역할·배정 인물·제보 내용·봉쇄 항목은 공개하지 않는다.
- 같은 방 버전에서 서로 다른 두 좌석이 동시에 능력을 사용하면 한 요청만 적용된다. 나머지는 버전 충돌로 거절되며, 자원은 차감되지 않는다. 최신 버전에서 다시 요청하면 한 번 적용되고, 같은 요청을 재전송해도 중복 차감하지 않는다.
- 로그아웃 없이 새 로그인으로 접속해도 기존 방·역할·기억 진행·준비 완료 상태를 복원한다. 기존 로그인 토큰은 폐기된다.
- 수사 방향 제안, 증언 신청, 용의자 정체 메모는 준비 완료·현재 차례·공식 증거·감식 키트를 소비하지 않는다. 증언 신청은 미검증 자료이며 공식 진술로 자동 승격되지 않는다. 용의자의 정체 메모는 본인에게만 보인다.
- 이미 확보한 원본을 다시 조사하면 방 버전·게임 날짜·수사 단계·자원이 그대로 유지된 채 거절된다.
- 탐정의 개인 단서로 확정된 질문과 공개 증거로 해결된 항목의 봉쇄는 거절된다. 조사권·봉쇄 횟수·준비 가능 상태는 유지된다.
- 저장된 기존 7일 사건의 진행 방식을 임의로 바꾸지 않는다.

`tests/seven-service.test.cjs`의 4개 검증도 통과했다. 6개 로그인 좌석으로 실제 서비스 함수를 호출하며, 다음 4개 결말을 각각 DAY 1–7까지 진행한다.

1. 탐정 정답과 용의자 제보 성공.
2. 범인 진영 승리와 용의자 개인 승리의 동시 성립.
3. 용의자 본인이 최종 고발되었을 때 패배 우선 적용.
4. DAY 6 준비 완료 뒤와 DAY 7의 제보 거절 및 미제보 결과.

새 사건의 비밀 준비는 좌석 역순으로 수행하여, 순차 진행만 가능한 구현이 테스트를 우연히 통과하지 못하도록 했다. 공식 질문은 탐정에게 허용된 최신 가정 목록에서 선택한다. 재로그인, 진영 공유 거짓말·유보 한도, 답변 검증 결과만 공개, 최종 인물 고발, 모든 좌석의 동일한 사건 복기, 재시작까지 확인한다.

실제 로컬 서버 `http://127.0.0.1:4217/`에서도 동일한 4개 결말을 통과했다. `docs/PACING-LOCAL-HTTP.json`에 다음 결과를 저장했다.

| 항목 | 결과 |
| --- | ---: |
| 실제 HTTP 요청 | 558 |
| 동시 참가 좌석 | 6 |
| 7일 전체 진행 결말 | 4 |
| 대표 차례가 아닌 좌석의 비밀 준비 | 140 |
| 준비 상태 확인 | 200 |
| 비밀정보 투영 확인 | 447 |
| 무료 제안·증언·정체 메모의 비용과 비밀성 확인 | 3 |
| 재로그인 | 13 |
| 좌석별 동일한 복기 대조 | 24 |
| 공개 연결 경로 대조 | 1,728 |

별도 테스트 계정만 사용하고, 종료 뒤 방을 재시작하여 참가자를 모두 퇴장시켰다. 이는 로컬 메모리 서버 확인이며 운영 Supabase·Vercel의 검증을 뜻하지 않는다.

## 대기 감소의 의미

7일간 개인별 순차 진행은 인원수에 따라 14·21·28·35·42개의 순차 차례를 만든다. 개편 후에는 온라인에서 모두 같은 비밀 준비 단계 안에서 선택할 수 있어 준비 단계의 진행 장벽이 7개로 합쳐진다.

각자의 준비 완료 입력 자체는 남는다. 준비 완료는 전략적 능력을 쓰지 않는 선택이므로, 준비 완료 수를 없어진 클릭이나 새로 생긴 유효 능력 수로 해석하지 않는다. 공개 기록을 확인하고 제안·증언·메모를 남기는 행동은 능력과 별도로 사용할 수 있다.

## 정책 시뮬레이션

2–6인 각각 100개 시드, 순차·동시 진행 두 방식으로 총 1,000개 사건을 종료했다. 모든 판단은 해당 좌석의 `privateView`만 컴퓨터 정책에 전달했다. 불법 행동·진행 교착·공식 증거가 실제 범인을 제외하는 경우는 0건이었다. 재현 명령은 `node tests/seven-pacing-policy.cjs`이며 결과는 `docs/PACING-POLICY.json`에 있다.

비교 대상은 **현재 같은 사건 자료와 컴퓨터 정책에서 진행 방식만 순차/동시로 바꾼 것**이다. 과거 운영 버전 승률과 직접 비교하는 수치가 아니다.

| 인원 | 순차 진행 탐정 승리 / 100건 | 동시 진행 탐정 승리 / 100건 | 순차 미진술 답변 | 동시 미진술 답변 |
| --- | ---: | ---: | ---: | ---: |
| 2 | 66 | 61 | 0 | 0 |
| 3 | 47 | 58 | 123 | 36 |
| 4 | 45 | 56 | 164 | 29 |
| 5 | 40 | 56 | 198 | 16 |
| 6 | 40 | 62 | 151 | 6 |

동시 진행 컴퓨터는 기억한 항목을 먼저 증언 신청하고 탐정은 미해결 신청을 질문 후보로 검토한다. 그 결과 다인 게임에서 정보 없는 대상에게 질문하고 미진술로 끝나는 경우가 줄었다. 신청 자체는 공식 증거가 아니며, 답변 제한·거짓말·감식 횟수는 그대로 적용된다.

6인 100건에서 기존 개인 패스는 3,522회, 개편 후 능력 없이 준비를 마친 선택은 3,518회였다. 따라서 **할 수 있는 강한 능력의 횟수가 늘었거나 모든 패스 입력이 사라졌다는 뜻은 아니다.** 개편의 효과는 개인 순서를 기다리는 장벽을 합치고, 준비와 별도로 제안·증언에 참여할 기회를 제공하는 데 있다. 정책은 6인 100건에서 미검증 무료 제안·증언을 4,200회 제출했다.

컴퓨터 정책의 승률은 사람 대전 승률을 뜻하지 않으며, UI 조작성·대화의 재미·다인 심리전의 균형은 실제 플레이 관찰이 추가로 필요하다. 이 결과만으로 인원별 균형을 조정 완료했다고 판정하지 않는다.

## 통합 및 브라우저 확인

전체 자동 테스트 235개가 통과했고 빌드, 기존 보안 검사 20개와 인증 경합 검사 5개도 통과했다. 기존 검사만으로 새 기능을 판단하지 않고 위 동시 준비·무료 참여·기록 대조 검사를 함께 실행했다.

실제 Chrome에서 6인 탐정 연습의 역할 확인·동시 준비·증언 신청 표시를 확인했다. 이어 2인 탐정 연습에서 시간 질문을 선택하고 미니 수첩의 시간 카드 12개를 확인한 다음 원래 질문으로 돌아와 값이 유지되는 것을 확인했다. 공식 질문·답변·감식 키트 사용·DAY-02 이야기 전환까지 직접 진행했다.

390×844 및 360×640 화면에서 질문 확정·수사 넘김 버튼이 창 안에 있고 터치 영역은 44px였다. 작은 화면의 시간 카드 12개도 창 안에 모두 표시됐다. 인물 상세에서 본인 관찰에 의한 제외와 공개 기록에 의한 제외를 구분하고 실제 적용된 관찰·연결 조건을 표시했다. 큰 상세 자료와 원본 목록은 필요한 경우 내부 읽기 영역을 사용하며 전체 메인 보드를 다시 설계한 버전은 아니다.

배포 이후의 운영 주소·정적 파일 일치·실제 신규 사건 요청 결과는 별도 릴리스 보고서에서 확인한다. 운영 검증은 새로 만든 테스트 방에서만 진행하며 기존 사용자 방에 테스트 행동을 보내지 않는다.
