# 마지막 목격자 — 온라인 · 무료 연습 4.2

**플레이:** [마지막 목격자](https://the-last-witness-pi.vercel.app/)
**소스:** [GitHub 저장소](https://github.com/cozyai1997/The-Last-Witness)

2~6명이 자기 브라우저로 같은 방에서 **7일간** 조사하는 한국어 추리 게임이다. 새 온라인·연습 사건은 규칙 4.2의 탐정 규칙 2로 시작한다. 참가자는 역할과 별도로 인물 12명 중 서로 다른 캐릭터를 배정받으며 범인(C)의 캐릭터가 진범이다. 장소는 12곳, 실제 사건에 연결된 도구와 시간대도 각각 12종이다. 최종 고발은 DAY 7 수사와 검토 후 인물 하나로 판정한다. 장소·도구·시간대는 인물과 연결된 수사 증거다. 범행 당일 18:00~21:00을 나눈 15분 시간대 12개와 이후 7일간의 수사 날짜는 구별한다.

용의자(S)는 탐정 편이 아닌 **중립 개인 역할**이다. 본인 후보 3명에서 기억 회복 두 번으로 3→2→1을 확인하고 DAY 1~6 본인 개인 행동 중 한 번 진범 캐릭터와 이유를 봉인 제보한다. 제보는 수정·철회·정오답 응답이 없다. 최종 인물이 본인 캐릭터면 제보 정오와 무관하게 실패한다. 그 외 정확 제보는 개인승리, 오제보·미제보는 생존·목표미달이다. 범인과 S의 동시승리도 가능하다.

새 사건은 동시 비밀 준비 흐름(`flowVersion: 2`)과 `detectiveVersion: 2`를 명시해 시작한다. 탐정은 전체 9개 항목 중 서로 다른 2개의 참인 초기 답을 받고, 질문은 하루 1회·진술 검증은 사건 전체 2회다. 원본 조사 행동은 새 사건에서 제공하지 않는다. 이미 시작한 7일 사건은 저장된 진행 방식과 탐정 규칙·자원을 유지한다. `detectiveVersion`이 없는 저장 사건은 기존 규칙 1이며 엔진의 기본 생성도 기존 호환을 유지한다. 규칙 3 사건도 기존 5일·8인물·4장소·기존 판정 그대로 이어간다. 기존 사건의 역할·정답·자원·기록을 초기화하지 않는다.

4.2에서도 수사 제안·증언 신청·용의자 정체 메모를 차례와 별개로 남길 수 있다. 증언 신청은 검증 전 제안이며 탐정이 정식 질문으로 채택하고 대상이 답변해야 공식 진술이 된다. 행동창의 미니 수첩에서 남은 후보·제외 근거·이전 질문을 확인할 수 있고 시작 확답·이미 확인한 내용과 같은 판정의 중복 검증은 서버에서도 거절한다. [탐정 개편 검증](docs/DETECTIVE-VERIFICATION.md)에 현재 확인 범위를 기록했다.

## 함께 시작하기

1. 닉네임과 8~16자 비밀번호로 가입하거나 기존 계정에 로그인한다. 기존 17~128자 비밀번호 계정은 계속 로그인할 수 있다. 이메일·전화번호는 받지 않는다.
2. 한 명이 방을 만들고 초대 링크나 방 코드를 공유한다. 2~6명이 준비하면 방장이 시작한다. 방장은 탐정 배정을 보장받지 않는다.
3. 자기 역할·캐릭터·관찰자료를 확인한다. 탐정 역할만 공개하며 범인·공범은 서로를 안다. S의 정체는 기억 회복 전까지 본인도 모른다.
4. 매일 동시 비밀 준비 → 증언·제안 검토 → 탐정 질문 한 번 → 답변·검토 → 확인을 진행한다. DAY 1~6 확인은 다음 날, DAY 7 확인은 최종 고발로 이어진다.
5. 모든 단계에서 하단 자유 채팅을 사용할 수 있다. 공식 증거·진술과 자유 의견은 구분된다.

[온라인 규칙](docs/ONLINE-RULES.md)에 인원별 역할, 관찰자료, 봉인·보호·유보·진술 검증, S 튜토리얼과 승패 예시를 정리했다. [7일 설계](docs/SEVEN-DAY-SPEC.md), [7일 검증 기록](docs/SEVEN-VERIFICATION.md)에서 구현 계약과 실제 확인 범위를 구분한다.

## 로그인 없는 연습

2~6인 구성에 실제로 존재하는 모든 역할 또는 무작위를 선택해 연습한다. S는 4~6인, 공범은 6인에 있다. 새 연습은 온라인과 같은 규칙 4 엔진을 사용하며 브라우저 메모리에서만 진행한다. 계정·방 API와 브라우저의 온라인 로그인 저장소를 사용하지 않는다. 새로고침하면 연습은 종료된다.

컴퓨터는 공개 기록과 본인 privateView만 받는다. 탐정은 실제 숨은 정답으로 고발하지 않고 후보에서 선택한다. 범인·공범만 허용된 사건 정답·동료 정보를 사용한다. S 컴퓨터도 기억 회복으로 얻기 전 자기 캐릭터를 읽지 않는다. 목격자는 아는 참만 답하고 모르면 기억 불명으로 답한다. 탐정 규칙 2의 S는 단서·정체 회복 여부와 관계없이 공식 답변을 기억 불명으로 남긴다. 공개 null 응답 문구는 모든 역할에 같으며 S의 역할을 인증하지 않는다. 정책 검사는 실제 사람끼리의 승률·재미 검증이 아니다.

## 진행과 기록

새 사건은 하루 한 명을 대상으로 질문하거나 질문을 넘긴다. 대상에는 S를 포함한 탐정 외 모든 닉네임이 역할 표시 없이 남는다. 전원에게 같은 질문을 일괄 배포하는 단체 질문은 구현하지 않았다. 기억 불명·유보·봉쇄로 끝나도 그날 질문은 사용하며 다음 날 재시도할 수 있다. 과거 진술과 방금 답변의 참·거짓 검증은 **사건 전체 2회**를 공유하고 질문 기회나 하루를 끝내지 않는다. 질문 전·답변 검토 중에 고를 수 있으며 답변 대기 중에는 쓸 수 없다. 이미 판정되었거나 초기 답·공개 정보로 참·거짓을 아는 내용과 같은 판정의 반복 진술은 걸러 자원을 쓰지 않는다. 공개 연결 자료와 기존 기록은 계속 읽을 수 있다. 원문·발언자는 보존한다. 기존 저장 사건의 원본 조사·공동 키트 1개 규칙은 유지한다.

공식 거짓 답변은 범인·공범 합계 두 번, 답변 유보는 별도 합계 한 번이다. C 봉인 두 번·A 봉인 한 번·S 보호 한 번이며 봉인은 이미 확보한 증거를 삭제하지 않는다. S의 기억 회복은 봉인할 수 없다. 이야기·이미지·프로필·제보 접수는 미확인 정답·S 정체·타인 배정을 미리 알려주지 않는다.

사건 종료 후에만 전체 역할·캐릭터, 네 좌표의 진상, S 제보와 개인 결과, 같은 사건 복기를 공개한다. 복기는 원래 답변과 당시 검증 여부를 보존하며 자유 채팅의 진위는 판정하지 않는다. 이전 사건은 남은 기록만 표시한다. 새 사건 준비·시작 전에 복기를 확인해야 하며 영구 사건 보관함은 제공하지 않는다.

도입·날짜 전환·결말의 손글씨 장면은 빠르게 보기·건너뛰기를 지원한다. BGM은 음악 버튼으로 직접 시작하며 음량 설정은 기기에 남는다. 개인 화면은 창 전환 시 가려진다.

## 재연결과 개인정보

닉네임과 비밀번호로 다시 로그인하면 같은 자리·캐릭터·차례·관찰자료·자원·제보를 이어간다. 새 로그인은 이전 토큰을 폐기한다. 로그아웃은 자리를 보관하고 방 나가기는 자리를 반납한다. 진행 중 입장·강퇴·자리 양도·재시작은 지원하지 않는다.

접속 토큰·닉네임은 탭 sessionStorage에 두고 비밀번호는 브라우저 저장소에 넣지 않는다. 세션은 24시간 뒤 만료해도 계정은 다시 로그인할 수 있다. 방은 마지막 플레이·운영 행동부터 30일 보관하며 폴링으로 연장하지 않는다. 기존 게스트의 현재 자리 저장도 지원하지만 이미 잃은 게스트 토큰은 닉네임만으로 복구하지 않는다.

서버가 비밀 배정·정답·차례·자원·승패를 관리한다. 클라이언트가 제출한 역할·참가자 ID·정답은 권한 근거가 아니다. 갱신은 버전 비교와 요청 번호로 중복 처리를 막는다. 모든 응답은 공개 기록과 인증된 본인의 허용 정보만 제공한다.

public/seven-data.js는 공개 목록·판정 보조 코드다. public/seven-practice-engine.js는 로컬 연습용 규칙 코드이며 온라인 실제 사건 상태를 담지 않는다. 로컬 연습은 개발자 도구로 정답을 찾는 행위를 방어하는 보안 모드가 아니다.

## 로컬 실행과 검사

Node.js 22 이상에서 실행한다.

~~~sh
npm ci
npm test
npm run test:security
npm run test:auth-review
npm run build
npm start
~~~

기본 주소는 http://127.0.0.1:4174 다. 별도 저장소 환경변수가 없으면 프로세스 메모리를 사용하므로 서버 재시작 시 로컬 방·세션이 사라진다. 공용 영속 저장소 검증을 대신하지 않는다.

실행 중인 대상에 실제 계정·방을 만드는 7일 HTTP 검사는 다음처럼 명시적으로 실행한다.

~~~sh
BASE_URL=http://127.0.0.1:4174 node tests/seven-live-http.cjs
~~~

PowerShell에서는 먼저 $env:BASE_URL을 설정한다. 검사는 새 임시 검증 계정과 방을 사용하며 결과에는 비밀번호·토큰·방 코드를 저장하지 않는다. 6인 7일 흐름, S 기억·제보·마감·재로그인, 실제 C 캐릭터 정답 판정, S 실패·중립 결과의 별도 사건, 복기와 재시작을 확인한다. 테스트가 성공했다는 기록과 실제 사람 6명의 대화·장기 균형은 구분한다. 기존 tests/live-http.cjs는 규칙 3 전용 기록·검사로 남겨 두었다.

생성 이미지 원본·프롬프트는 .IMG/, 웹 자산은 public/images/에 보관한다. BGM 제작 기록은 [BGM](docs/BGM.md), 이전 버전 인수 이력은 [인수 검사](docs/ACCEPTANCE.md)에 있다.

## 프로덕션 설정

배포 환경은 SUPABASE_URL, SUPABASE_ANON_KEY, WITNESS_STORE_SECRET 세 값을 사용한다. [.env.example](.env.example)은 이름만 제공하며 실제 비밀값은 커밋하지 않는다. 파일을 복사하는 것만으로 개발 서버가 환경변수를 읽는다고 가정하지 않는다.

[저장소 SQL](scripts/storage.sql)의 __SECRET_SHA256__를 서버 비밀값의 SHA-256 해시로 바꾼다. 원문은 서버의 WITNESS_STORE_SECRET에 둔다. 운영에서 저장소 설정이 빠지면 메모리로 조용히 전환하지 않는다. 기존 저장소를 새 규칙 때문에 초기화하거나 마이그레이션하지 않는다.

데이터는 비공개 스키마에 저장하고 직접 접근 권한과 RLS를 제한한다. 공개 RPC는 서버 비밀 검증과 버전 비교를 거친다. [Supabase Data API 보안](https://supabase.com/docs/guides/api/securing-your-api), [데이터베이스 함수](https://supabase.com/docs/guides/database/functions)를 참고한다. 로컬 검사·빌드·배포 준비·실제 운영 수락은 [7일 검증 기록](docs/SEVEN-VERIFICATION.md)에 별도로 기록한다.

## GUI 개편 4.3

사진 비율·상세 창·질문 입력·결과 조작과 창 전환 잠금은 4.3.1에서 다시 수정했다. 원인과 실제 브라우저 확인 범위는 [GUI 복구 기록](docs/GUI-REPAIR-2026-10-18.md)에 있다.

청록 상황실, 익명 참가자, 인물·장소·도구·시간의 12개 카드, 종이 심문 창과 하단 메뉴를 적용했다. 게임 규칙은 4.2와 기존 저장 사건의 규칙을 유지한다. 생성 재질 3종의 원본·프롬프트·매핑과 전체 298개 테스트, 보안 20개·인증 5개 검사 결과는 [GUI 개편 검증 기록](docs/GUI-REMAKE-2026-10-18.md)에 있다. Edge 모바일 뷰포트 확인과 물리 기기 검증은 구별하며, 전체 브라우저 진행·운영 배포 확인 상태도 해당 기록에서 확인한다.
