# 마지막 목격자 — 온라인

2~6명이 각자의 브라우저로 같은 방에 접속해 즐기는 한국어 추리 게임이다. 닉네임으로 게스트 접속한 뒤 방 코드를 공유한다. 탐정은 최대 5라운드 동안 NPC 사건 인물 8명 중 한 명과 장소 4곳 중 한 곳을 찾아낸다.

사람에게 배정되는 탐정·범인·목격자·용의자·공범 역할은 사건판의 NPC와 별개다. 역할은 자동으로 배정되며 탐정의 신원만 공개한다. 범인·공범은 서로와 사건 정답을 알고, 나머지 참가자에게는 자기 단서만 전달한다.

## 함께 시작하기

1. 닉네임을 입력해 게스트로 접속한다. 닉네임은 본인 인증이나 영구 계정이 아니다.
2. 한 명이 방을 만들고 초대 링크 또는 방 코드를 공유한다. 다른 참가자는 같은 방에 입장한다.
3. 2~6명의 참가자가 모두 준비하면 방장이 시작한다. 방장은 로비 운영자이며 탐정 역할을 보장받지 않는다.
4. 각자는 자기 정보 화면에서 자기 역할과 단서를 확인한다. 현재 차례인 참가자만 개인 행동이나 답변을 할 수 있다.
5. 매 라운드 전원 개인 행동, 탐정 수사 한 번, 공개 토론 순으로 진행한다. 최종 지목은 탐정이 한다.

자세한 규칙은 [온라인 규칙](docs/ONLINE-RULES.md), 확인 범위와 남은 검사는 [인수 검사 기록](docs/ACCEPTANCE.md)을 참고한다.

## 새로고침과 재연결

현재 탭의 게스트 세션을 사용해 새로고침 후 같은 방 상태를 다시 받는다. 화면은 활성 탭에서 약 2초 간격으로 서버 상태를 확인한다. 잠시 연결이 끊겨도 역할과 사건을 브라우저에서 새로 만들지 않는다. 행동의 성공 여부는 다시 받은 서버 상태로 확인한다.

게스트 토큰은 탭의 `sessionStorage`에 보관한다. 탭을 닫거나 저장소를 지우면 원래 게스트로 돌아오지 못할 수 있다. 같은 닉네임을 다시 입력해도 기존 참가자의 신원을 복구하는 인증 수단은 아니다. 세션은 로그인 때부터, 방은 생성 때부터 24시간 유효하며 폴링으로 연장되지 않는다.

## 서버와 개인정보

서버가 사건 정답·역할·턴·자원·최종 승패를 관리한다. 클라이언트가 제출한 역할, 참가자 ID, 정답, 거짓말 잔량은 권한의 근거로 삼지 않는다. 방 상태를 갱신할 때 버전 비교를 사용해 동시에 제출한 행동의 중복 처리를 막는다.

모든 참가자에게 보내는 정보는 공개 사실·진술·메모·차례와 탐정 신원이다. 개인 정보는 인증된 현재 참가자 본인에게만 보낸다. 범인 편에게 필요한 정답·동료 정보도 그 진영의 본인 응답에서만 제공한다. 사건 종료 뒤에는 정답과 전체 역할을 공개한다.

자기 정보 패널은 직접 열어 확인하며 창을 떠나면 닫힌다. 이는 화면의 우연한 노출을 줄이는 기능이다. 같은 기기를 다른 사람에게 넘길 때는 자기 정보 화면을 닫고 세션 취급에 주의해야 한다. 초대 코드는 방 입장 수단이며 본인 인증이나 비밀 역할 열람 권한을 대신하지 않는다.

## 인터페이스

서버 요청은 `POST /api/room`을 사용하며 `login`, `create`, `join`, `poll`, `ready`, `start`, `action`, `restart`, `leave`, `kick` 작업을 처리한다. 게임 행동과 권한을 검사하는 서버 코드, 저장소 처리, 공개 화면은 분리한다. 클라이언트에 원본 게임 상태나 서버 비밀값을 포함하지 않는다.

## 로컬 실행

Node.js 22 이상에서 다음 명령을 사용한다.

```sh
npm ci
npm test
npm run build
npm start
```

기본 주소는 `http://127.0.0.1:4174`다. 별도 저장소 환경변수가 없으면 로컬 실행은 프로세스 메모리를 사용하므로 서버를 재시작하면 방과 세션이 사라진다. 이 모드는 여러 배포 인스턴스의 공용 저장소 검증을 대신하지 않는다.

## 프로덕션 설정

배포 환경에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `WITNESS_STORE_SECRET` 세 값을 설정한다. 변수 이름은 [.env.example](.env.example)에 있다. 파일을 복사하는 것만으로 개발 서버가 자동으로 환경변수를 읽는다고 가정하지 않는다. 설정값은 실행 환경에 주입하며 실제 비밀값을 저장소에 커밋하지 않는다.

게임 전용 저장소에는 [저장소 SQL](scripts/storage.sql)을 적용한다. SQL의 `__SECRET_SHA256__`는 서버 전용 비밀값의 SHA-256 해시로 바꿔야 한다. 원문 비밀값은 `WITNESS_STORE_SECRET`로 서버에만 둔다. 운영 환경에서는 설정이 빠졌다고 메모리 모드로 조용히 전환하지 않는다.

데이터는 비공개 스키마의 테이블에 보관하고 테이블 직접 접근 권한과 RLS를 제한한다. 공개 RPC는 서버 비밀값을 검증한 뒤에만 읽기·버전 비교 갱신을 허용한다. 권한 부여와 RLS의 역할은 [Supabase Data API 보안 문서](https://supabase.com/docs/guides/api/securing-your-api), 함수 권한과 실행 맥락은 [데이터베이스 함수 문서](https://supabase.com/docs/guides/database/functions)를 참고한다.

저장소 연결·다중 인스턴스·브라우저 확인 결과를 [인수 검사 기록](docs/ACCEPTANCE.md)에 구분해 기록하며, 자동 검사 결과를 실제 사람의 승률이나 재미 검증으로 해석하지 않는다.
