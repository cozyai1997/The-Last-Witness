# 마지막 목격자 — 온라인 · 무료 연습 3.3

**플레이:** [마지막 목격자](https://the-last-witness-pi.vercel.app/)

**소스:** [GitHub 저장소](https://github.com/cozyai1997/The-Last-Witness)

2~6명이 각자의 브라우저로 같은 방에 접속해 즐기는 한국어 추리 게임이다. 닉네임과 비밀번호로 가입한 뒤 방 코드를 공유한다. 탭을 닫거나 다른 기기로 이동해도 다시 로그인하면 기존 자리·역할·진행을 이어간다. 탐정은 최대 5라운드 동안 NPC 사건 인물 8명 중 한 명과 장소 4곳 중 한 곳을 찾아낸다.

사람에게 배정되는 탐정·범인·목격자·용의자·공범 역할은 사건판의 NPC와 별개다. 역할은 자동으로 배정되며 탐정의 신원만 공개한다. 범인·공범은 서로와 사건 정답을 알고, 나머지 참가자에게는 자기 단서만 전달한다.

## 함께 시작하기

1. 닉네임과 **8~16자 비밀번호**로 가입하거나 기존 계정에 로그인한다. 기존에 17~128자 비밀번호로 만든 계정은 그 비밀번호로 계속 로그인할 수 있다. 이메일·전화번호는 받지 않는다.
2. 한 명이 방을 만들고 초대 링크 또는 방 코드를 공유한다. 다른 참가자는 같은 방에 입장한다.
3. 2~6명의 참가자가 모두 준비하면 방장이 시작한다. 방장은 로비 운영자이며 탐정 역할을 보장받지 않는다.
4. 자기 차례가 오면 역할 확인·개인 행동·답변 화면이 자동으로 열린다. 현재 차례인 참가자만 행동할 수 있으며, 창을 떠나면 개인 화면은 가려진다.
5. 매일 개인 행동과 탐정 수사 한 번을 진행한 뒤 결과를 검토한다. 탐정이 확인을 누르면 1~4일은 다음 날로, 5일은 최종 고발로 이어진다. 자유 채팅은 진행 중 어느 단계에서도 사용할 수 있다.

새로 시작하는 **2인전은 탐정의 시작 단서 두 개를 공식 자료로 자동 공개**하고 탐정의 개인 행동을 생략한다. 범인만 봉인 또는 넘기기를 선택한 뒤 탐정이 수사한다. 3인 이상은 각 참가자의 단서 공개·제안·역할 능력 선택을 유지한다. 이미 진행 중인 이전 버전 사건을 이 특례 때문에 초기화하지 않는다.

새 2~6인 사건의 탐정은 **사건 인물 특성 1개와 현장 특성 1개**를 참 단서로 받는다. 목격자는 나머지 항목에서 한 개씩 받는다. 완료한 질문·모름·은폐로 막힌 항목과 탐정이 아는 단서는 새 질문과 가정 목록에서 제외한다. 새 질문이 없으면 진술 검증이나 수사 넘기기로 진행할 수 있다. 현장 감식은 아직 진실을 확정하지 못한 항목을 다시 확인할 수 있다.

최종 고발은 공식 증거·탐정의 참 단서와 내 제외 메모를 반영한 인물·장소만 표시한다. 내 메모는 확정 증거가 아니므로 잘못 제외했다면 초기화할 수 있다. 검증된 거짓 답변은 빨간 테두리로 표시한다. 은폐 안내는 문구가 끝난 뒤 계속할 수 있고, 실패 결과는 범인에게만 보인다. [3.3 변경과 검사 기록](docs/DETECTIVE-FEEDBACK-VERIFICATION.md)을 참고한다.

공동 수사는 하루 한 번, 키트는 전체 한 개다. 감식과 과거 진술 검증은 그날 수사와 키트를 함께 쓴다. **방금 받은 이진 답변은 결과 검토 중 같은 키트로 즉시 검증**할 수 있으며 추가 공동 수사를 사용하지 않는다. 키트가 추가로 생기는 것은 아니고, 원문·발언자·확정 사실은 보존한다.

자세한 규칙은 [온라인 규칙](docs/ONLINE-RULES.md), 최신 확인 범위는 [몰입형 진행·연습 검증](docs/IMMERSIVE-VERIFICATION.md), 계정과 음악의 이전 검사 이력은 [3.1 검증](docs/ACCOUNT-BGM-VERIFICATION.md)을 참고한다.

## 로그인 없이 무료 연습

2~6인 구성을 고르고 탐정·범인·무작위 역할로 컴퓨터 참가자와 연습할 수 있다. 연습은 브라우저 메모리에서만 진행하며 온라인 계정·방을 만들거나 변경하는 API를 호출하지 않는다. 연습을 끝내도 기존 온라인 계정과 방 상태는 바뀌지 않으며, 새로고침하면 연습 사건은 종료된다.

컴퓨터의 판단에는 해당 역할이 볼 수 있는 공개 기록과 자기 단서만 전달한다. 탐정 컴퓨터는 실제 정답을 보지 않고 후보를 추리하며, 범인 편은 규칙상 허용된 정답·동료 정보를 사용한다. 정직한 역할은 아는 항목만 참으로 답하고 모르는 항목에는 모름으로 답한다. 연습 상대는 규칙을 익히기 위한 정책이며 사람끼리의 실제 승률·사회적 균형을 검증한 결과가 아니다.

## 화면과 이야기

도입, 매일의 전환, 최종 고발과 결말에 짧은 손글씨 장면이 나온다. 빠르게 보기·건너뛰기와 Enter·Esc로 진행할 수 있으며 이야기 장면이 수사 횟수를 추가로 소비하지 않는다. 질문은 사건 속 NPC의 관찰 내용을 확인하는 문장이다. 선택한 질문의 주장 값은 연출용이며 답변의 참거짓을 바꾸지 않는다.

개인 화면은 자기 차례에 자동으로 열리고 창을 떠나면 가려진다. 기록 아이콘에서는 공식 증거·진술·후보를 확인하고 자원 설명에서는 키트·거짓말·능력 한도를 살펴본다. 하단 채팅은 진행 중 상시 사용할 수 있다. 결과 화면에서는 패배 진영을 회색으로 구분한다.

## 새로고침과 재연결

새로고침 후 현재 로그인으로 같은 방 상태를 다시 받는다. 탭을 닫았으면 닉네임과 비밀번호로 다시 로그인한다. 별도의 방 코드 입력 없이 기존 방으로 돌아오며 역할·차례·단서·능력 사용량과 진행 기록이 유지된다. 화면은 활성 탭에서 약 2초 간격으로 서버 상태를 확인한다. 잠시 연결이 끊겨도 역할과 사건을 브라우저에서 새로 만들지 않는다.

접속 토큰과 닉네임을 탭의 `sessionStorage`에 보관하며 비밀번호는 브라우저 저장소에 넣지 않는다. 새 로그인은 기존 접속 토큰을 폐기한다. 로그아웃은 서버의 자리를 유지하고, '방 나가기'는 참가 자리를 반납하는 서로 다른 기능이다. 계정은 서버에 저장되며 접속 토큰의 24시간 만료 후에도 다시 로그인할 수 있다. 방은 마지막 플레이·방 운영 행동 이후 30일 동안 보관하며 단순 폴링으로 기간을 연장하지 않는다.

이전 버전의 게스트가 현재 탭에 남아 있다면 '현재 자리 저장'에서 비밀번호를 등록해 같은 자리를 계정에 연결한다. 이미 탭을 닫아 게스트 토큰을 잃은 과거 자리는 닉네임만으로 가져올 수 없다. 비밀번호 찾기·이메일 복구는 제공하지 않는다.

## 배경음악

오리지널 누아르 BGM을 재생·일시정지하고 음량을 조절할 수 있다. 처음에는 멈춘 상태이며 음악 버튼을 눌러 재생한다. 음악 파일과 제작 기록은 `public/audio/`, [BGM 기록](docs/BGM.md)에 있다. 음악 설정은 이 기기에만 적용된다.

## 서버와 개인정보

서버가 사건 정답·역할·턴·자원·최종 승패를 관리한다. 클라이언트가 제출한 역할, 참가자 ID, 정답, 거짓말 잔량은 권한의 근거로 삼지 않는다. 방 상태를 갱신할 때 버전 비교를 사용해 동시에 제출한 행동의 중복 처리를 막는다.

모든 참가자에게 보내는 정보는 공개 사실·진술·메모·차례와 탐정 신원이다. 개인 정보는 인증된 현재 참가자 본인에게만 보낸다. 범인 편에게 필요한 정답·동료 정보도 그 진영의 본인 응답에서만 제공한다. 사건 종료 뒤에는 정답과 전체 역할을 공개한다.

자기 차례의 개인 화면은 자동으로 열리며 필요하면 내 정보를 다시 열 수 있다. 창을 떠나면 개인 화면을 닫아 우연한 화면 노출을 줄인다. 초대 코드는 방 입장 수단이며 본인 인증이나 비밀 역할 열람 권한을 대신하지 않는다.

온라인 실제 사건의 전체 상태는 서버에만 두고 각 참가자에게 허용된 정보만 전달한다. 별도의 공개 파일 `public/practice-engine.js`는 로컬 연습에 쓰는 순수 규칙 코드다. 규칙 코드의 공개와 온라인 실제 사건의 비밀 상태 공개는 구별한다. 연습은 기기 안에서 사건을 계산하므로 개발자 도구를 이용한 연습 정답 확인을 막는 보안 모드로 취급하지 않는다.

## 인터페이스

온라인 서버 요청은 `POST /api/room`을 사용하며 `register`, `login`, `logout`, `create`, `join`, `poll`, `ready`, `start`, `action`, `restart`, `leave`, `kick` 작업을 처리한다. 게임 행동과 권한을 검사하는 서버 코드, 저장소 처리, 공개 화면은 분리한다. 온라인 응답에는 실제 사건의 전체 원본 상태나 서버 비밀값을 포함하지 않는다. 로컬 연습은 이 방 API를 사용하지 않는다.

## 로컬 실행

Node.js 22 이상에서 다음 명령을 사용한다.

```sh
npm ci
npm test
npm run test:security
npm run test:auth-review
npm run build
npm start
```

기본 주소는 `http://127.0.0.1:4174`다. 별도 저장소 환경변수가 없으면 로컬 실행은 프로세스 메모리를 사용하므로 서버를 재시작하면 방과 세션이 사라진다. 이 모드는 여러 배포 인스턴스의 공용 저장소 검증을 대신하지 않는다.

실행 중인 서버를 7개의 독립 계정으로 검사하려면 `BASE_URL`을 대상 주소로 지정한 뒤 `node tests/live-http.cjs`를 실행한다. 테스트는 새 검증용 방을 만들고 최대 6명 입장, 5라운드, 승패, 재시작을 검사한다. 실제 사람 6명의 대화나 장기 승률을 대신하지 않는다. 생성 이미지 원본과 프롬프트는 `.IMG/`, 웹용 이미지는 `public/images/`에 보관한다.

## 프로덕션 설정

배포 환경에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `WITNESS_STORE_SECRET` 세 값을 설정한다. 변수 이름은 [.env.example](.env.example)에 있다. 파일을 복사하는 것만으로 개발 서버가 자동으로 환경변수를 읽는다고 가정하지 않는다. 설정값은 실행 환경에 주입하며 실제 비밀값을 저장소에 커밋하지 않는다.

게임 전용 저장소에는 [저장소 SQL](scripts/storage.sql)을 적용한다. SQL의 `__SECRET_SHA256__`는 서버 전용 비밀값의 SHA-256 해시로 바꿔야 한다. 원문 비밀값은 `WITNESS_STORE_SECRET`로 서버에만 둔다. 운영 환경에서는 설정이 빠졌다고 메모리 모드로 조용히 전환하지 않는다.

데이터는 비공개 스키마의 테이블에 보관하고 테이블 직접 접근 권한과 RLS를 제한한다. 공개 RPC는 서버 비밀값을 검증한 뒤에만 읽기·버전 비교 갱신을 허용한다. 권한 부여와 RLS의 역할은 [Supabase Data API 보안 문서](https://supabase.com/docs/guides/api/securing-your-api), 함수 권한과 실행 맥락은 [데이터베이스 함수 문서](https://supabase.com/docs/guides/database/functions)를 참고한다.

저장소 연결·다중 인스턴스·브라우저 확인 결과를 [인수 검사 기록](docs/ACCEPTANCE.md)에 구분해 기록하며, 자동 검사 결과를 실제 사람의 승률이나 재미 검증으로 해석하지 않는다.
